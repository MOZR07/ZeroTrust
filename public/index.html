Kebutuhan 4.1 1. Uji Penetrasi: Direct Access Bypass Port 3001 (Tanpa Gateway Secret)

Yang dijelaskan: Penyerang mencoba menembak Service Nilai (port 3001) langsung tanpa melewati API Gateway. Service resource menolak karena tidak ada header X-Gateway-Secret (HTTP 403 Forbidden).

Kebutuhan 4.1 2. Prinsip Assume Breach: Verifikasi Ulang Token di Resource Service

Yang dijelaskan: Penyerang berhasil memalsukan X-Gateway-Secret namun tidak membawa JWT valid. Service resource tetap menolak (HTTP 401 Unauthorized) karena memverifikasi ulang token secara independen.

Kebutuhan 4.3 3. Verifikasi Konteks: Login Ditolak Jika Device ID Asing

Yang dijelaskan: Username dan password benar, tapi menggunakan header X-Device-ID: DEV-PENYUSUP-HP yang tidak terdaftar di database. Policy Engine langsung menolak (HTTP 403 Forbidden).

Kebutuhan 4.3 4. Verifikasi Konteks: Edit Nilai di Luar Jam Operasional (Pukul 23.00)

Yang dijelaskan: Dosen yang sah mencoba mengubah nilai pada pukul 23:00 malam (di luar batas 07:00–21:00). Policy Engine menolak dengan pesan pembatasan jam operasional.

Kebutuhan 4.2 5. Kontrol Akses Data (ABAC): Dosen Lain Dilarang Ubah Nilai Kelas Budi

Yang dijelaskan: Dosen Siti mencoba mengubah nilai kelas IF301 (milik Dr. Budi). Policy Engine membaca relasi kepemilikan kelas di SQLite dan menolak request (HTTP 403 Forbidden).

Kebutuhan 4.2 6. Privasi Mahasiswa: Mahasiswa Ditolak Mengintip Transkrip Orang Lain

Yang dijelaskan: Mahasiswa Andi (227006001) mencoba mengakses transkrip Rani (227006002). Policy Engine menolak karena identifier subjek tidak sama dengan NIM target.

Kebutuhan 3 & 4.1 7. Finalisasi Kelas & Komunikasi Antar-Service dengan Service Token

Yang dijelaskan: Dr. Budi memfinalisasi kelas -> status nilai terkunci -> Service Nilai meminta Service Token ke Gateway -> Service Nilai memanggil Service Transkrip via Gateway PEP.

Kebutuhan 4.2 8. Proteksi Endpoint Sinkronisasi: Token User Biasa Ditolak Keras

Yang dijelaskan: Tabel 3 PDF mensyaratkan POST /transkrip/sinkron hanya boleh dipanggil dengan token ber-role service. Token user (bahkan Admin) ditolak mentah-mentah.
